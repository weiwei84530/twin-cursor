ttk design constraints

Target: tkinter/ttk on Windows 10/11 · base font Segoe UI 9pt · fixed-size, non-resizable window

✅ Safe to design with

  • Flat colors for every surface: window background, frames, buttons, fields, text — including full dark themes
  • Per-state colors: hover, pressed, focused, disabled
  • 1px solid borders and their colors
  • Font family (system-installed only), size, bold/italic
  • Padding, margins, gaps, overall spacing rhythm
  • Title bar background color (Windows 11, via DWM)
  • Checkbox / accent color (via a custom ttk theme)
  • Simple raster icons next to labels or on buttons

🚫 Not expressible in ttk

  • Rounded corners on widgets (window corners come from DWM only)
  • Drop shadows, glows, blur, translucency
  • Gradients of any kind
  • Animations and transitions (hover fades, sliding, etc.)
  • Custom scrollbars, sliders, toggle switches
  • Styling the open dropdown list of a combobox (it is a native Windows popup)
  • Letter-spacing, variable font weights, web fonts
  • Resizing the native check glyph or combobox arrow
  • Free-form layouts — the window is a fixed grid of rows

How to hand changes back

  • Express the design as tokens: a flat list of colors, font sizes and paddings (see the :root variables in settings-window.html). Editing those variables is the preferred way to restyle — each one maps directly to a ttk style option.
  • Keep the widget set unchanged: 2 labeled group boxes, each with a readonly dropdown, a checkbox, a button and a small caption line. Adding new widget types means new Python code, not just styling.
  • The hotkey button must fit both of its texts: Hotkey: Ctrl+Alt+M and Press keys… (Esc = none).
  • If a wanted effect sits in the red column, note it as a comment instead of styling it in — it needs a discussion about switching the UI stack (e.g. WebView) rather than a CSS tweak.
